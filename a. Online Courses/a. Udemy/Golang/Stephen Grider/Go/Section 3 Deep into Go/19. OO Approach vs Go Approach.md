### Structuring Code in Go vs. Object-Oriented Programming

While Go is not a traditional Object-Oriented Programming (OOP) language like Java or Python, it has powerful features that allow for similarly organized and maintainable code. This guide explains the difference in approach and how we'll structure our `cards` project.

#### The Object-Oriented (OO) Approach

In a typical OO language, you might solve the cards problem by creating a **`Deck` class**. A class acts as a blueprint for creating objects. This `Deck` class would define:

- **Properties**: Data associated with a deck, such as a `cards` property that holds an array of strings.
- **Methods**: Functions that belong to the class and operate on its data, like `shuffle()`, `deal()`, and `print()`.

You would then create an _instance_ of this class to represent a specific deck and call methods on that instance to manipulate it.

#### The Go Approach: Custom Types and Receiver Functions

Go achieves a similar outcome without using classes. The approach consists of two main parts:

1. Creating a Custom Type

Instead of a class, we define a new custom type. In our project, we will create a deck type that is based on Go's existing slice of strings type. This is done in the deck.go file.

Go

```Go
// in deck.go
// This creates a new type named 'deck' which is like a slice of strings.
type deck []string
```

This new `deck` type behaves just like a `[]string`, but now we can add our own custom functions to it.

2. Adding Functionality with Receivers

To add methods to our new deck type, we create special functions called receiver functions. A receiver "attaches" a function to a specific type, making it callable on any variable of that type.

A receiver is a special argument that comes before the function name.

**Syntax**: `func (v variableName typeName) functionName() {}`

For example, to create a `print` function that works on our `deck` type, we would write:

Go

```Go
// in deck.go
// The (d deck) part is the receiver.
// It makes this function available on any variable of type 'deck'.
func (d deck) print() {
	for i, card := range d {
		fmt.Println(i, card)
	}
}
```

With this code, we can now call the `print` method on a `deck` variable, just like we would in an OO language:

Go

```Go
// in main.go
cards := newDeck()
cards.print() // This works because of the receiver function.
```

### Project File Structure

As a project grows, it's best practice to separate code into multiple files for better organization. For the cards project, we will use the following structure:

- **`main.go`**: This file will contain the starting point of our application (`func main`). It will be responsible for creating a deck and using the functions we define to manipulate it.
- **`deck.go`**: This new file will contain all the logic related to the `deck` type. This includes the type definition (`type deck []string`) and all the receiver functions that work with it (`newDeck`, `print`, `shuffle`, etc.).
- **`deck_test.go`**: This file will be added later and will contain code to automatically test our deck logic, ensuring it works correctly.

**Important Rule**: Every file within a single package must start with the same package declaration. Since all our files are part of the same application, both `main.go` and `deck.go` must begin with the line `package main`.
