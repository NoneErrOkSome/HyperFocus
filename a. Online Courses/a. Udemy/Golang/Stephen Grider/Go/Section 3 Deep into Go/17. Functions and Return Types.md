### Functions and Return Types in Go

In Go, functions are fundamental for organizing and reusing code. A key feature is the ability to return values. Because Go is a statically-typed language, you must be explicit about the type of data a function will return.

#### The Goal: Creating a Value-Returning Function

Instead of assigning a value directly to a variable within our `main` function, a better practice is to delegate that logic to a separate function. Our goal is to create a `newCard` function that returns a `string` representing a card, which we can then assign to a variable in `main`.

Here is the code we are working towards in `cards/main.go`:

Go

```Go
package main

import "fmt"

func main() {
	// Call a function to get the card value
	card := newCard()

	fmt.Println(card)
}

// newCard is declared to return a value of type 'string'
func newCard() string {
	return "Five of Diamonds"
}
```

#### Declaring a Function's Return Type

In Go, you must explicitly state what type of value a function will return. If you try to return a value from a function that isn't declared to have a return type, the compiler will give you an error.

For example, this initial attempt would fail:

Go

```Go
func newCard() { // No return type declared
	return "Five of Diamonds" // But we are returning a string
}
```

The compiler would produce an error like: `too many arguments to return; have string, want empty`. This error is Go's way of telling you that the function signature promises no return value, but the function body is trying to return a `string`.

**The Solution** is to add the return type to the function's signature, right after the argument list.

The correct syntax is:

func functionName (parameters) returnType { ... }

**Example:**

Go

```Go
// By adding 'string' here, we tell Go this function will return a string.
func newCard() string {
	return "Five of Diamonds"
}
```

#### Type Inference with Function Calls

Go's type system is smart. When you call a function that has a declared return type, Go uses that information for type inference.

Consider this line:

Go

```Go
card := newCard()
```

Even though we are using the short `:=` syntax, the Go compiler knows that:

1. The `newCard()` function is declared to **always** return a value of type `string`.
2. Therefore, the variable `card` must also be of type `string`.

This allows you to use the convenient `:=` operator while still maintaining the safety and predictability of a static type system.

#### The Compiler is Your Friend

The strictness of Go's type system is a feature designed to help you write correct code. The error messages are usually very clear and descriptive.

For instance, if you were to change the return type of `newCard` to `int` but forget to change the value you're returning:

Go

```Go
func newCard() int { // Promises to return an integer
	return "Five of Diamonds" // But tries to return a string
}
```

The Go compiler would give you a helpful error:

cannot use "Five of Diamonds" (type string) as type int in return

Instead of being intimidating, these errors should be seen as a guide. The compiler is telling you exactly what is wrong: you promised an `int` but provided a `string`. Reading these messages carefully is a key part of learning to program effectively in Go.
