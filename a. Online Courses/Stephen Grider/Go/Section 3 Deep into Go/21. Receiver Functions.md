### Understanding Receiver Functions in Go

In the last section, we created a `print` function with a new piece of syntax called a **receiver**. A receiver is what connects a function to a custom type, making it behave like a "method" for that type.

#### What is a Receiver?

A receiver is a special argument in a function declaration that gives any variable of a specific type access to that function.

In our `cards` project, we added a receiver of type `deck` to our `print` function. Because of this, any variable of type `deck`, like the `cards` variable in our `main.go` file, can now call `print()` using dot notation (`cards.print()`). This is the primary purpose of a receiver: to add methods to our custom types.

---

### Breaking Down the Receiver Syntax

Let's look closely at the syntax of the `print` function in `deck.go`:

Go

```Go
func (d deck) print() {
	// ... function code ...
}
```

The `(d deck)` part is the receiver. It consists of two parts:

1. **`d` (The Receiver Variable)**: This is the name given to the actual instance of the variable the function is called on. When you run `cards.print()` from `main.go`, the `cards` variable is passed into the `print` function as `d`. It's a reference to the working copy of the deck.
    
2. **`deck` (The Type)**: This specifies that the `print()` function is "attached" to the `deck` type. Only variables of type `deck` can call this function with dot notation.
    

#### Naming Convention for the Receiver

By convention in Go, the receiver variable is a one or two-letter abbreviation of its type. In this case, `d` is used for `deck`. While you could name it anything (e.g., `myDeck`, or even `this`), the Go community strongly prefers the short, abbreviated name. This might seem unusual if you're used to other languages that advise against single-letter variables, but it is the standard Go idiom.

### An Analogy to Object-Oriented Programming (OOP)

If you have a background in OOP languages like Java, Python, or JavaScript, you can use the following analogies to help understand Go's approach:

- **Custom Type (`deck`) + Receiver Functions (`print()`)**: This combination is _vaguely_ like a **Class** in OOP. The type defines the data, and the receiver functions define its behavior.
- **Receiver Variable (`d`)**: This is very similar to the `this` or `self` keywords in other languages. It refers to the specific instance of the object the method is being called on.

**Important**: It's crucial to remember that **Go is not an object-oriented language**. We do not use terms like "class." This is simply a helpful mental model for understanding the relationship between custom types and the functions that operate on them. This pattern of creating custom types and attaching receiver functions is one of the most common and powerful patterns in Go.
